Getting started

Installation

Runes2P needs Julia 1.13. It is not registered in the General registry and is added from its repository:

using Pkg
Pkg.add(url = "https://github.com/osrep/Runes2P.jl")

The HDF5 output is a package extension. It loads with using HDF5 next to using Runes2P and defines write_output and read_output. Checkpoints need it loaded.

The examples run from a checkout of the repository. Their environment, examples/Project.toml, takes Runes2P from the parent directory and adds HDF5:

julia --project=examples -e 'using Pkg; Pkg.instantiate()'   # once
julia --project=examples examples/relaxation.jl
julia --project=examples examples/cooling.jl scheme=van_albada solver=gmres
julia --project=examples examples/avalanche.jl treatment=implicit solver=gmres

The examples

Each script solves one kinetic equation for the electron distribution $f(p, \xi, r)$ and runs without arguments. Its header lists its default values and further command lines.

The plasma values of relaxation.jl and the biuniform_270 grid are choices of this package (Choices of this package). The plasma of cooling.jl is that of reference/dream/cases/cooling_positivity.py, cooled over 2 ms where that case takes 1 ms, with the radial values of DREAM's SPI example. Its grid and time step are a choice of this package. avalanche.jl takes the values of its DREAM example, among them superthermal collisions, the energy-dependent Coulomb logarithm and DREAM's ion-size table. Its interpolation scheme is the default of this package, where the example uses TCDF (scheme=tcdf). Its switch treatment= of KnockOnTerm is explicit_primary (the primary distribution at the previous time level, as in DREAM), explicit (the whole term there) or implicit. implicit takes the whole term at the new time level and applies it matrix-free in each Krylov iteration of GMRES. The direct solver does not take it, so with treatment=implicit the solver defaults to GMRES.

Every script prints the segment and its status, the solver statistics (SolverStatistics), the negative entries of the saved states and the density per radius at every save. In a GMRES run the statistics include the Krylov iterations and factorizations. Before the timed run a script integrates over the first three time points, so that the timing leaves out the compilation. relaxation.jl and cooling.jl end with exit_status as the exit status of the process.

The parts of a run

The three scripts build a run in the same order.

  1. A MomentumGrid from momentum faces (uniform_p_faces, biuniform_p_faces, tanh_p_faces) and pitch faces (uniform_xi_faces, biuniform_theta_xi_faces), combined with a RadialGrid by cylindrical_grid (Grids).
  2. A PlasmaState with its IonSpecies, and the CollisionSettings of the collision frequencies (Collision models).
  3. The kinetic operator, an AdvectionDiffusion with its interpolation schemes and boundaries (Positivity and flux limiters).
  4. An UnknownLayout with one KineticUnknown :f, and an EquationSystem of one Equation: a TimeDerivative and the terms, among them FokkerPlanckTerm or prescribed_fokker_planck_term (Unknowns and the equation system).
  5. A NewtonSolver with its linear solver, and integrate over the time points, which returns a TimeSolution (Time stepping and solvers).

The shared helpers of the scripts are in examples/common.jl: the switches, a Maxwell-Jüttner initial state normalized with density, the report and the output.

avalanche.jl takes neither the checkpoint, stop and log switches nor the grid and plasma switches of common.jl. Its own are treatment=, cutoff= (the knock-on cutoff momentum), np=, np_low=, nxi= and e_over_ec=, the field in multiples of the critical field of the total electron density.

The examples precondition GMRES with RadiusBlockLU, factorize it once per step and restart after 30 iterations, unlike the defaults of GMRES.

The default scheme, exponential fitting, is a choice of this package (Choices of this package); its properties, the other schemes and DREAM's default are on the page Positivity and flux limiters.

With nonnegative=true, a Newton step that would push an entry already at zero below it fails with :below_lower_limit (LowerLimit, NewtonSolver), and FixedSteps retries it with half the time step. At a low temperature on a wide grid, the Maxwell-Jüttner tail underflows to exact zeros, so such a run rejects and halves many steps. Shorter steps do not remove a round-off negative update of an entry at zero; a positive tolerance of the LowerLimit does.

In a Slurm job with checkpoints, the segment stops before the end of the job without further switches: StopCondition takes SLURM_JOB_END_TIME as its end.

The settings of a run

integrate records the settings of the run with run_settings before the first step and returns them in settings of the TimeSolution. Each object of the package the run is built from has a describe record, and the record collects them by section.

  • The setup: grids, layout, system, updates, prescribed, solver, time and run, each with a settings_hash and a hash of them together.
  • run holds the description that a script passes to integrate, such as the name of the example and the origin of its initial state.
  • Outside the hashes: code (code_version, with the commit of Runes2P when it runs from a git checkout, as the examples do, and "unknown" for an installed package), environment, checkpoint, stop and log.
  • segment: the number, the start, the status and the reason of a stop of this segment.

The record is taken before a stored state is restored, so restoring does not change it. A resumed segment whose setup differs lists the changed sections in its segment record. complete is false when some object of the run has no record of its own, such as a term defined outside the package.

Output files

output=run.h5 writes the solution with write_output: the saved states per unknown, the layout, the solver statistics and the settings record. read_output reads it back as a TimeSolution, and read_settings reads the settings record alone.

checkpoint=name writes, in checkpoint_dir=, the files that CheckpointSettings names.

  • name.checkpoint.h5, the last checkpoint, and name.checkpoint.prev.h5, the one before it.
  • name.segment<k>.h5 (k with four digits), the output of segment k.

A run that stops writes its checkpoint and exits with exit_status, so that a batch script can start the next segment with resume=true. read_output with the CheckpointSettings of the run joins its segments into one solution:

using Runes2P, HDF5
solution = read_output(CheckpointSettings("cooling"; directory = "run"))
f_end = unknown_view(solution.states[:, end], solution.layout, :f)   # f at the last save

The format of these files is on the page Output files.
