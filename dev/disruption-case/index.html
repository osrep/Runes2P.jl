The disruption case

This page compares Runes2P with DREAM in DREAM's disruption case. The tests compare with DREAM release v26.5, whose outputs of the case are reference sets of the page Reference data.

The reference case is DREAM's disruption of examples/Disruptions/generate.py, scenario 1, in a cylinder. Its case script is reference/dream/cases/disruption_kinetic.py (Reference data). The tests run the case at a reduced size, fully kinetic and in DREAM's superthermal mode. The whole quenches of scenarios 1 and 4 at full size are measurements that no test repeats.

The runs of the case script

The case script runs DREAM's chain of generate.py as six runs, 0 to 5. Run 5 needs the option --window-start.

RunWhat it does
0one step: the conductivity of the initial plasma and the field of the prescribed current profile
11 s in 3 steps from the Maxwellian with that field
2run 1 again, with the field rescaled to the plasma current
3the ionization phase (phase 1): the ionization of the injected D and Ar
4the thermal and current quench (phase 2)
5a window of phase 2: run 4 stops at a saved step, and run 5 takes the next steps from DREAM's state there

Runs 0 to 2 are the initialization.

The initialization in Runes2P:

  • Runes2P runs the initialization itself, as runs 0 to 2.
  • The field and the cold temperature stay at their prescribed values in runs 1 and 2.
  • Runes2P builds the state at the start of phase 1 from the end of run 2 and the ions of the settings.

The runaway grid

The runaway grid is the case script's --runaway-grid (Choices). build adds it with runaway = true.

  • The flux of f_hot through the hot-tail p_max enters f_re and n_re (MomentumInterfaceTerm, InterfaceParticleFluxTerm).
  • The kinetic avalanche source acts on f_re, on the runaway grid.
  • The fluid avalanche acts in n_re, which counts every electron above the hot-tail p_max. On the runaway grid the fluid avalanche equals the kinetic source of f_re, and in n_re it adds the tail beyond the runaway grid's p_max.
  • f_re carries the runaway current, ionizes the ions and heats the cold electrons.
  • In the window of run 5, the runaway current is 5.9 % of the plasma current at the start.

Balances checked without DREAM

The tests of the phases, of the chains and of the runaway grid also check balances of the assembled system that do not need DREAM. They check them at both compat values. The test of the initialization checks none. field is one value over the whole run, from the first state to the last. Every other value is the worst over the steps.

How to repeat it

  1. DREAM runs the case script with the command line of "The run" above.
  2. read_dream_state reads DREAM's output of run 4.
  3. run_window runs Runes2P over the saved times of a DREAM run, here all 429 steps of the quench.
  4. phase_differences returns the largest difference of each quantity.

  • The largest difference, 1.12e-5, is in the first step, in the lowest momentum cell.
  • It falls to 1.5e-8 by step 20.

  • Its cause is not established.

How to repeat it

The default diffusivity of build and run_window of test/example_disruption.jl is that of scenario 1. So the run of scenario 4 needs diffusivity = 1000.0.

  1. read_dream_state reads DREAM's output of run 4.
  2. run_window(start, :dream; diffusivity = 1000.0, solver) runs the quench, with a NewtonSolver on MKLPardiso.
  3. phase_differences returns the largest difference of each quantity.
